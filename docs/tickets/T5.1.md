# T5.1 — Load the hadith collections (L2) into Neo4j (agy)

**Goal:** add the hadith layer that Phase 5 links to: `HadithBook`, `Hadith`, `Grader`, `IN_BOOK` and `GRADED`.
It reads the 10 pinned fawazahmed0 editions, writes one JSONL file, and adds a loader and tests.
It is deterministic and uses no LLM. agy **does not write to the real Neo4j**: Claude runs the load after Aya & Mohamed approve.
Linking (`CITES`) comes in later tickets.

## Facts (measured by Claude, 2026-11-17)
- Source: `data/raw/hadith/fawazahmed0/ara-<collection>.json`, commit `df57907` (`docs/decisions.md`, T1.3).
  Each file has `metadata` (`name`, `sections`, `section_details`) and `hadiths`. Each hadith has the keys `hadithnumber`, `arabicnumber`, `text`, `grades` and `reference` (`{book, hadith}`).
- Of the **36,512** entries, **408 have empty `text`**. They are not loaded (schema.md) and never filled. That leaves **36,104** hadith:

  | collection | loaded | English name (metadata) | Arabic name (`HadithBook.name`) |
  |---|---|---|---|
  | abudawud | 5,272 | Sunan Abu Dawud | سنن أبي داود |
  | bukhari | 7,580 | Sahih al Bukhari | صحيح البخاري |
  | dehlawi | 40 | Forty Hadith of Shah Waliullah Dehlawi | الأربعون للدهلوي |
  | ibnmajah | 4,338 | Sunan Ibn Majah | سنن ابن ماجه |
  | malik | 1,829 | Muwatta Malik | موطأ مالك |
  | muslim | 7,360 | Sahih Muslim | صحيح مسلم |
  | nasai | 5,679 | Sunan an Nasai | سنن النسائي |
  | nawawi | 42 | Forty Hadith of an-Nawawi | الأربعون النووية |
  | qudsi | 40 | Forty Hadith Qudsi | الأحاديث القدسية الأربعون |
  | tirmidhi | 3,924 | Jami At Tirmidhi | جامع الترمذي |

- **Numbers:**
  - `hadithnumber` is an int, except **26 Bukhari values that are floats** (e.g. `402.2`). The `hadith_id` number part is a string: `str(int)` for ints, `str(float)` for floats (`bukhari:402.2`). There are 0 duplicates per collection.
  - `arabicnumber` is a **string in Muslim** (`"493.01"`, `"492"`) and an int elsewhere. Store it as a string, unchanged (`str(value)`).
  - **148** loaded Muslim entries have no `arabicnumber` key, so they get `arabic_number = null`.
  - Muslim footnotes in the tafsir cite `arabicnumber` (decisions.md, T2.1). It is the main key for T5.2.
- **Grades:**
  - **67,334** grade entries come from **9 graders**: Zubair Ali Zai 19,033; Al-Albani 18,925; Shuaib Al Arnaut 6,409; Abu Ghuddah 5,609; Muhammad Muhyi Al-Din Abdul Hamid 5,169; Muhammad Fouad Abd al-Baqi 4,309; Ahmad Muhammad Shakir 3,667; Bashar Awad Maarouf 2,384; Salim al-Hilali 1,829.
  - No hadith has two grades from the same grader.
  - **15,106** loaded hadith have no grade. This includes all of Bukhari, Muslim and the three forty-hadith books.
  - There are 1,671 distinct grade strings. Store each one exactly as in the source (hard rule 2), and never infer a grade.
- Neo4j today: L0/L1 plus 128,499 spans, **0 Hadith / HadithBook / Grader**. The constraints for `HadithBook.collection`, `Hadith.hadith_id` and `Grader.name`, and the indexes on `Hadith.arabic_number` and `Hadith.collection`, already exist (`src/graph/schema.cypher`).

## Steps
1. **Parse to JSONL:** new `src/ingest/parse_hadith.py` writes `data/interim/hadith/hadith.jsonl`, one line per loaded hadith, sorted by collection then source order:
   `{"hadith_id", "collection", "number", "arabic_number", "book_number", "number_in_book", "text", "text_norm", "grades": [{"grader", "grade"}]}`.
   - `text` is verbatim.
   - `text_norm` comes from `src/extract/normalize.py` (`normalize_with_map(text)[0]`, the same normalizer as the tafsir). Phase 5 matching uses it.
   - `book_number` is `reference.book` and `number_in_book` is `reference.hadith`.
   - Also write `data/interim/hadith/books.jsonl` with 10 rows: `collection`, `name` (the Arabic name from the table), `name_en` (metadata `name`) and `edition` (`"ara-<collection>"`).
   - Never edit `data/raw/`.
2. **Loader:** new `src/graph/hadith.py` with `load_hadith(driver, hadith_path, books_path)`. It uses `MERGE` on the unique keys and `UNWIND` batches like `src/graph/load.py`, and writes:
   - `(:HadithBook {collection, name, name_en, edition, source})`
   - `(:Hadith {hadith_id, collection, number, arabic_number, book_number, number_in_book, text, text_norm})`
   - `(:Grader {name})`
   - `(:Hadith)-[:IN_BOOK]->(:HadithBook)`
   - `(:Hadith)-[:GRADED {grade}]->(:Grader)`

   Rules:
   - Every relationship gets `source: "hadith-api@df57907"`, `method: "dataset"` and `confidence: 1.0` (hard rule 4, decisions.md Q3).
   - Running the load twice must not change any count.
   - Add `CREATE FULLTEXT INDEX hadith_text_norm_ft IF NOT EXISTS FOR (n:Hadith) ON EACH [n.text_norm]` to `src/graph/schema.cypher`.
3. **Task:** in `scripts/tasks.py`, add a `hadith` target. `hadith` parses and prints the counts; `hadith --write` also loads into Neo4j.
4. **Tests** (`tests/test_hadith_load.py`):
   - The parse gives exactly the counts in the Facts table: total 36,104; per collection; 67,334 grades; 9 graders; 15,106 without a grade; 148 `arabic_number` null; 26 float numbers.
   - `muslim` entries with `arabicnumber` `"2865.01"` have `hadith_id` `muslim:7207`, and the text contains «خلقت عبادي حنفاء» (decisions.md T2.1).
   - `bukhari:402.2` exists.
   - `text` equals the raw text byte for byte for 20 random hadith (fixed seed).
   - **Loader test on a tiny fixture only.** Use the collection name `test-coll` with ids `test-coll:1…3` and grader `test-grader`. Load it twice and check the counts are unchanged and that provenance is on every edge. Then delete **only** those nodes.
     The test must never touch the real collections. If Neo4j is not reachable, the test skips.
5. Run `python scripts/tasks.py test`; every test must pass.
6. Update `docs/schema.md` (the `Hadith.text_norm` property, the fulltext index and `HadithBook.name_en`) and add a dated entry to `docs/decisions.md` with the measured counts. Write the report `docs/tickets/reports/T5.1.md` and set the TRACKER row to `review`. Commit with a message that starts with `T5.1:`. **Do not push, and do not run `hadith --write`.**
