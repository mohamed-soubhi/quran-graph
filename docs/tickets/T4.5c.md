**Goal:** recover hadith and athar that the whole-book run missed, by asking GLM again with a clearer prompt, but only on
windows where it found nothing and the text shows a narration cue. Also fix `kind` on chained takhrij lines with an offline rule.

  In a sample of 10, read against `docs/notes/phase4-annotation-rules.md`: 5 clear misses (athar with a full isnad, e.g. «وَقَالَ ابْنُ أَبِي حَاتِمٍ: حَدَّثَنَا أَبِي … سَمِعْتُ عِكْرِمَةَ يَقُولُ»;
  takhrij lines with their own route, e.g. «وَرَوَاهُ ابْنُ جَرِيرٍ مِنْ حَدِيثِ أَيُّوبَ، عَنْ مُحَمَّدِ بْنِ سِيرِينَ، عَنْ عُبَيْدَةَ»), 2 unclear, 3 correctly empty

  GLM disagrees with the span above in 236 of 1,092 such lines (`.scratch/chained_rule.py`): 174 lines labelled `athar` under a `marfu` hadith, 62 the other way. 8 of 8 sampled were wrong labels.

## Steps
1. **Prompt 1.3** (`ANCHOR_SYSTEM_PROMPT`, `PROMPT_VERSION = "1.3"`). Make it match the annotation rules more clearly; **do not change the rules themselves**:
   - Rule 1: say that reports of Companions and Successors (`athar`) **are** HADITH spans when they come with an isnad (حدثنا / أخبرنا / سمعت) or a takhrij verb + collector (رواه / أخرجه / روى),
     even when the content is tafsir; `kind` = `athar`.
   - Rule 4: a takhrij line with its own route («رواه X من حديث / من طريق Y … به», «… بنحوه») is its own span **even when the hadith it refers to is not in this window**.
   - Rule 6: "short route" means a name + «عن» + a name with no transmission verb and no takhrij (as in the rules file). Stories and dreams stay COMMENTARY.
   - Add one new few-shot example (written by you, not taken from the book or `data/gold`): an athar with a full isnad followed by a chained takhrij line, both `athar`.
   - Keep everything else (JSON-only answer, escaped quotes, collection list, footnote rule).
2. **Gate** — `python scripts/eval_4b.py --runs 3` with prompt 1.3 must pass (P ≥ 90 %, R ≥ 80 %, mean IoU ≥ 0.9 in every run). Gold set and thresholds unchanged.
   Report the numbers beside T4.5b's (P 91.7/100/100, R 91.7/95.8/91.7, IoU 0.998/0.976/0.996) and, separately, recall on the gold `athar` spans only.
3. **Select windows** — new `scripts/select_recheck_windows.py`: read `hadith-raw.jsonl` (latest `ok` per key), keep keys whose parsed answer has **0 spans** and whose window text,
   **with footnote characters removed using the footnote positions of the whole segment** (so a window that starts or ends inside a `[[…]]` is handled), normalized, matches
   `حدثن|اخبرن|سمعت|رواه|اخرجه|اخرجا`. Write the keys, sorted, one per line, to `data/interim/spans/recheck-keys.txt`. Print the count (expect a little under 1,508).
4. **Runner** — `scripts/run_hadith_book.py --keys-file PATH`: run only those keys. The second pass writes to its own file:
   `--raw-path data/interim/spans/hadith-raw-pass2.jsonl`. Resume, progress and the stop rule work as now. **Never write to `hadith-raw.jsonl`.**
5. **Build** — `--raw-path` accepts several files, read in the given order; for the same key the later file's latest `ok` answer wins. Every kept span records the
   `prompt_version` of the answer it came from; totals print spans per prompt version.
6. **Kind rule** (in `--build`, after overlap resolution, spans in reading order per segment). A span takes the `kind` of the span before it when **all** hold:
   - its text, footnotes removed and normalized, starts (after punctuation) with an optional «و / ثم / فقد / وقد / هكذا / وهكذا / كذا / وكذا / كذلك / وكذلك» and then «رواه / اخرجه / اخرجاه»;
   - it contains the word «به»; it contains no «حدثن» or «اخبرن»; it is under 400 normalized characters;
   - the span before it is in the same segment and ends less than 300 characters before it starts.
   Use the previous span's kind **after** its own update, so a chain of takhrij lines follows the first hadith. When the kind changes, store `kind_glm` (GLM's value) and
   `kind_rule: "chained_takhrij"`. Print the number of changes per direction. On `hadith-raw.jsonl` alone: report the counts; Claude's count with the previous span's
   original kind is 236 (174 `athar`→`marfu`, 62 `marfu`→`athar`); with chains it may differ slightly — explain any difference over 10.
7. **Tests** (no network): prompt version stored in raw records; selection skips a window whose cue is only inside a footnote that started before the window; `--keys-file`
   restricts the windows; with two raw files the later answer wins; kind rule: «ورواه النسائي من حديث حماد به» after a `marfu` span → `marfu`; a line with «حدثنا» → unchanged;
   gap ≥ 300 → unchanged; over 400 characters → unchanged; a chain of two takhrij lines → both follow the hadith.
8. **Pilot** — select the keys, then `python scripts/run_hadith_book.py --keys-file data/interim/spans/recheck-keys.txt --raw-path data/interim/spans/hadith-raw-pass2.jsonl --limit 20`,
   then build both files into **scratch outputs** (`--out-path .scratch/hadith-pass2-pilot.jsonl --rejected-path .scratch/hadith-pass2-pilot-rejected.jsonl`). Report:
   windows ok/failed, how many of the 20 now have spans, spans by kind, and the kind-rule counts. Keep `hadith-raw-pass2.jsonl`; the full pass resumes from it. **Then stop.**
