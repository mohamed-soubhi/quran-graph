# T0.5 — Extraction smoke test

**Goal:** GLM returns schema-valid JSON for one tafsir paragraph, reliably.

## Inputs (provided by Claude)
- `tests/fixtures/tafsir_sample.txt` — Ibn Kathir 2:255, paragraph 0, verbatim (904 chars, UTF-8, no trailing newline).
- `tests/fixtures/tafsir_sample.expected.json` — hand-annotated draft: `hadith_spans` (2 hadith: Ahmad 141–657,
  Muslim 658–790) and full `spans` covering the paragraph (COMMENTARY / HADITH / FOOTNOTE).
- `scripts/build_fixture.py` — how the fixture was built (do not run in tests; needs the raw download).

## Steps
1. `src/extract/models.py`: pydantic `HadithSpan(start:int, end:int, cue:str, collection_hint:str|None, number_hint:str|None)`
   and `HadithSpanList(spans: list[HadithSpan])`.
2. `src/extract/glm_client.py`: call Ollama `/api/chat` with `format` = the JSON schema of `HadithSpanList`,
   `temperature: 0`, model from `GLM_MODEL` in `.env`.
3. Prompt = short English instruction + one few-shot example (write a short example of your own; do NOT use the
   fixture as the few-shot). Tell the model that text inside `[[…]]` is an editor's footnote, not a hadith.
4. Read the fixture with `encoding="utf-8"` and pass it unchanged. Validate with pydantic; check
   `0 <= start < end <= len(text)`; log seconds per paragraph to `logs/`.
5. Script `scripts/extract_smoke.py` runs it 5 times and, for each run, prints how many predicted spans overlap
   each expected hadith span (character overlap ≥ 50%). This is informational, not a pass/fail gate.
6. `tests/test_extract_models.py`: the expected `hadith_spans` from the fixture validate as `HadithSpanList`
   (no network needed).

## Acceptance
- Valid JSON in 5/5 runs; mean seconds per paragraph and the overlap results recorded in `docs/decisions.md`.
- `python scripts/tasks.py test` passes.
- Commit `T0.5: ...`.

## Background

quoted start/end phrases that code then locates (NFC + diacritic-insensitive, see `docs/decisions.md`).
Record what you observe about offset accuracy.
