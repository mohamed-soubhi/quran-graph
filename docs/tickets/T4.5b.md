# T4.5b — Reliable GLM answers + whole-book hadith runner (agy)

**Goal:** make GLM answers safe to parse, make failures visible, and build a resumable whole-book runner. agy tests it on a
200-window pilot and stops. **Claude starts the full run** (~36–45 hours at 4 parallel calls, approved by Aya & Mohamed
2026-11-03). Results go to files; writing to the real Neo4j happens only after review.

## Facts (measured by Claude from `logs/glm_client.log`, T4.5)
- About 350 calls: 5 first attempts failed, 1 failed twice. Kinds: unescaped `"` inside an Arabic string
  (`expected , or }`), text after the JSON (`{"spans": []}\n\n**Explanation…`), and `collection_hint: "tabari"`.
- So the Ollama cloud model **does not strictly enforce `format`**. One bad `collection_hint` currently loses the whole window.
- **Bug:** after the last failure `extract_hadith_anchors` returns an empty list, which looks the same as "no hadith here".
  At this rate that could silently lose dozens of windows over 12,770.
- `locate()` has no upper limit: an end anchor can match after the end of the window GLM was given.
- `write_spans` needs checking: `kind` must be stored on HADITH spans.

## Steps
1. **Prompt** (`ANCHOR_SYSTEM_PROMPT`; add a `PROMPT_VERSION` constant): the answer is exactly one JSON object and nothing
   else, with no explanation and no markdown; a `"` inside a string is written `\"`; `collection_hint` is one of the listed values,
   anything else is `"other"`. Make the few-shot outputs show an escaped quote. Do not weaken the existing rules.
2. **Parser** — pure function `parse_anchor_response(raw) -> ParsedAnchors` in `src/extract/glm_client.py`, no network:
   - take the first JSON object (as now), ignore fences and trailing text;
   - validate **span by span**: an unknown `collection_hint` becomes `"other"` (keep the span, count it); an invalid span is
     dropped and counted, the others are kept; an unknown `kind` drops the span;
   - no JSON object at all → raise `GlmResponseError`.
3. **No silent empties** — `extract_hadith_anchors`: up to 3 attempts, then raise `GlmExtractionError`. An empty list now always
   means GLM really answered "no spans". Update `scripts/eval_4b.py`, `scripts/hadith_throughput.py` and
   `extract_hadith_spans_for_segment`: a failed window is counted and printed. `eval_4b` fails the run if any window failed.
4. **Stay inside the window** — in `locate_and_check_anchors`, reject with reason `outside_window` unless
   `window_start <= start < end <= window_end`. Every rejection records a reason.
5. **Re-check the gate** — `python scripts/eval_4b.py --runs 3` must still pass (P ≥ 90 %, R ≥ 80 %, mean IoU ≥ 0.9 in every run).
   Do not change the gold set or the thresholds. Paste the before and after numbers in the report.
6. **Runner** `scripts/run_hadith_book.py`:
   - windows = `find_cue_paragraphs` + `split_long_paragraph` over all segments, in a fixed order; key `<segment_id>#<start>-<end>`;
   - `--concurrency` (default 4), `--limit N`; submit work in small batches so memory stays flat;
   - append one line per window to `data/interim/spans/hadith-raw.jsonl`, flushed immediately: key, status (`ok` | `failed`), the raw
     GLM text, error, model, `PROMPT_VERSION`, seconds, timestamp;
   - **resume:** on start, skip keys that already have status `ok`; `failed` keys are tried again. Killing the process at any moment
     loses at most the calls in flight; a half-written last line is ignored;
   - print progress every 100 windows: done / total, failed, seconds per call, hours left;
   - stop by itself, with a clear message and a non-zero exit code, if more than 20 % of the last 200 windows failed (cloud outage or quota).
7. **Build step** `--build` (no GLM calls, safe to repeat): read the raw file (latest `ok` per key), parse, locate, check, and write
   `data/interim/spans/hadith.jsonl` and `hadith-rejected.jsonl` (with reason). Spans from overlapping windows: identical offsets are
   merged; a partial overlap keeps the longer span and rejects the other with reason `overlap`. Print totals: windows ok, failed, with no span,
   spans by `kind`, rejected by reason, fallback count, length min/median/max.
   Records as in T4.5, plus `confidence`: **0.9**, or **0.8** when `fallback_used` (one GLM pass; agreement across runs is not available
   for the whole book, so record this change to the schema's `x-locator-rules` in `docs/decisions.md`).
8. **Writer** `python scripts/tasks.py hadith-spans --write`: reads `hadith.jsonl`, removes old HADITH spans first (only `type: 'HADITH'`), writes through
   `write_spans`, idempotent, stores `kind`. No links to `Hadith` nodes. **Do not run it against the real graph**; test it the way
   the existing span writer tests do.
9. **Tests** (no network), `tests/test_hadith_spans.py` or a new file: the three logged failures as raw strings (trailing text; a span
   with `collection_hint: "tabari"` is kept as `other`; unescaped quote → error, then retry); a mocked client failing 3 times raises and does
   not return empty; `outside_window` rejection; resume skips `ok` keys and retries `failed` keys; a half-written last line is ignored; the
   stop rule at > 20 %; build merges identical spans and rejects partial overlaps.
10. **Pilot** — `python scripts/run_hadith_book.py --limit 200`, then `--build`. Report windows ok/failed, attempts needed, rejections by reason, seconds per
    call, projected hours left, and memory use of the process. Keep the raw file: the full run resumes from it. **Then stop. Do not start the full run.**
