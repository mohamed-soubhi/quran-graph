## Deviations
- The ticket asked for Cypher files `tests/fixtures/g2/<case>.cypher`. Instead the fixture is **one JSON file built from
  the raw data by a script** (`scripts/build_g2_fixture.py` → `tests/fixtures/g2/cases.json`), and the test loads it.
  Reason: hand-typed offsets in Cypher could not be re-checked; now every offset is recomputed from `data/raw/` and
  the test fails if any span does not start with its recorded text.
- Schema v1.0 could not represent cases 1 and 3 as written (see "Schema changes" — needs your approval).

## Schema changes the real text required (v1.0 → v1.1) — need your approval
| # | Found in the text | v1.0 said | Proposed v1.1 |
|---|---|---|---|
| C1 | Quran quotes **inside** hadith (5 in Anas's hadith alone), and editor notes inside Quran quotes and inside hadith | Rule 1: spans never overlap; rule 2: a footnote *splits* a quote into pieces | **Nested spans:** `(:Span)-[:INSIDE]->(:Span)`. Top-level spans tile the segment (no overlap, 100 % coverage). A nested span lies inside exactly one parent; siblings never overlap. Nothing is split. |
| C2 | Ibn Kathir quotes isnads of collections we do not have (Musnad Ahmad) — there is no `Hadith` node to hang the chain on | `IN_CHAIN` only from `Hadith`; `HEARD_FROM.hadith_id` | `IN_CHAIN` also from a HADITH `Span` (with the narrator's mention offsets); `HEARD_FROM.chain_id` = hadith_id **or** span_id |
| C3 | Quran quotes are marked ﴿ … ﴾ (U+FD3F … U+FD3E) | not stated | QURAN spans include **both** brackets (like FOOTNOTE includes `[[ ]]`) |
| C4 | Ibn Kathir often writes the reference after a quote: «﴾ [الرُّومِ:٢٥]», «[مَرْيَمَ: ٩٣-٩٥]» | not stated | Phase 4a links these by regex first (`ref_text` on CITES); needs a surah-name → number table (Tanzil metadata, Phase 3) |

## Known limit for Phase 4b (no schema change)
A hadith can continue **after** an editor note («مَا أَحْلَلْتُ [[في ر: "ما حللت".]] لَهُمْ"», 4:116). An end anchor
cannot reach across the note today. Proposal for the Phase 4b ticket: anchor matching ignores footnote characters
(they are removed from the normalized copy, with the offset map kept).
