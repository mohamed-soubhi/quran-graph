# T4.5b Report — Reliable GLM answers + whole-book hadith runner + pilot (agy)

## Deviations & Review Findings (Claude 2026-11-04 Review)

The pilot run and review revealed six issues (F1 to F6) that were investigated, resolved, and verified prior to full-book execution:

1. **Runner Idling & Projected Time Correction (F1)**:
   - *What was reported initially:* ~42.0 hours whole-book projection calculated as `(windows * mean_sec / concurrency)`.
   - *What was actually measured:* The initial batching approach (submitting batches of 8 and waiting for the batch) caused thread idle time due to long-tail call variances (median 34s, max 392s). Actual measured wall time was 3,553s vs 2,370s at full utilization (67% utilization), meaning the whole-book run would have taken **~63 hours**, not ~42 hours.
   - *What was done:* Replaced batching with sliding-window concurrency (`concurrent.futures.wait(..., FIRST_COMPLETED)`), keeping at most `concurrency` calls in flight flatly. Both progress updates and the final summary now compute projected hours from real elapsed time per window (`elapsed / done`). Under sliding-window concurrency, thread utilization is expected to approach 100%, targeting ~42 hours, though this remains to be measured on a fresh full run.
2. **Silent Loss through `kind` (F2)**:
   - In 2 pilot windows (`ibn-kathir:1:1-1:1#61-3061` and `#12231-13954`), GLM returned `"kind": "marfu'"`. Because the parser previously expected exact `"marfu"`, 6 valid spans were silently dropped and both windows falsely appeared as "no span".
   - *What was done:* `parse_anchor_response` now normalizes `kind` by stripping accents and non-letters (`marfu'`, `marfū'`, `Marfu` -> `marfu`). Dropped spans are now captured in `hadith-rejected.jsonl` with `reason: "invalid_span"` and their raw values. `--build` now prints dropped spans and unknown collections.
3. **Anchors Skipping Footnotes (F3)**:
   - All 5 `not_found` rejections in the pilot occurred because GLM anchor phrases spanned across `[[...]]` editor footnotes (e.g. «أَبِي الْجَعْدِ [[…]] ، بِهِ»).
   - *What was done:* `locate()` now searches normalized text with footnote characters removed and whitespace collapsed, preserving a 1-to-1 character offset map to original verbatim text coordinates. Matches crossing footnotes are exact (confidence 0.9). Anchors occurring strictly inside footnotes return `None`. All 5 previously rejected spans now match cleanly.
4. **Boundaries Inside a Word (F4)**:
   - 5 pilot spans cut words: 4 started after a joined «وَ» (e.g. `وَ|قَالَ ابْنُ أَبِي حَاتِمٍ`), and 1 ended before a final hamza «سوا|ء» due to hamza skipping during normalization.
   - *What was done:* `locate()` expands `start` backwards and `end` forwards to whole word boundaries before applying closing-mark extension, keeping the whole span within window bounds. Word boundary cuts dropped from 5 to 0.
5. **Neo4j Deletion Safety (F5)**:
   - `test_neo4j_write_hadith_spans_stores_kind` previously called `delete_spans_by_type("HADITH")` on the real database, which would have wiped all HADITH spans on any test run after the full write.
   - `write_hadith_spans` previously called `delete_spans_by_type` before reading the input file.
   - *What was done:* `write_hadith_spans` reads and validates the file first, refusing empty or missing files before deleting old spans. Tests delete only their own test `span_id` and test `delete_spans_by_type` using a test-specific type (`TEST_DELETE_TYPE`). Real graph HADITH spans are never touched by tests.
6. **Half-Written Line Resilience (F6)**:
   - If a previous run was killed midway leaving a partial line without a newline, the next append would corrupt both records.
   - *What was done:* The runner ensures a trailing newline exists before appending. On stop-rule trigger, active in-flight calls are drained before closing the file.

## What Changed

1. **GLM Prompt & Parser Resilience (`src/extract/glm_client.py`)**:
   - `PROMPT_VERSION = "1.2"`.
   - Pure function `parse_anchor_response(raw: str) -> ParsedAnchors`:
     - Decodes first JSON object using `raw_decode`, ignoring surrounding markdown fences and trailing text.
     - `normalize_kind`: strips diacritics and non-letters so `marfu'`, `marfū'`, `Marfu` become `marfu`; `athar`, `Athar` become `athar`.
     - Validates span-by-span: unknown `collection_hint` mapped to `"other"` (counted); dropped spans preserved in `dropped_items` with raw values; raises `GlmResponseError` if no JSON object decoded.
   - `extract_hadith_anchors`: up to 3 retry attempts, raising `GlmExtractionError` on exhaustion.

2. **Footnote-Tolerant, Bounded Span Locator (`src/extract/locate.py` & `src/extract/hadith_spans.py`)**:
   - `locate()`:
     - Strips footnote characters and collapses whitespace in normalized text with an exact 1-to-1 character offset map to original text coordinates (F3).
     - Allows anchors to cross `[[...]]` footnotes while anchors exclusively inside footnotes return `None`. Crossing footnotes is exact (confidence 0.9).
     - Word boundary expansion (F4): expands `start` backwards and `end` forwards using `is_word_char` (letters, combining marks, numbers, tatweel) before closing-mark extension.
   - `locate_and_check_anchors`: enforces `window_start <= start < end <= window_end` with `reason: "outside_window"`. Every rejection records an explicit reason.

3. **Neo4j Span Writer Safety (`src/graph/spans.py`)**:
   - `write_hadith_spans`: reads and validates input file first, refusing missing or empty files before executing `delete_spans_by_type("HADITH")` (F5).

4. **Runner & Build Pipeline (`scripts/run_hadith_book.py`)**:
   - Sliding-window concurrency (`FIRST_COMPLETED`) maintaining at most `concurrency` calls in flight (F1).
   - Real elapsed wall time per window used for progress and summary hour projections (`elapsed / done`).
   - Trailing newline check on `hadith-raw.jsonl` before appending; stop rule drains in-flight calls before closing (F6).
   - `--build`: resolves overlapping spans, merges identical offsets, writes dropped spans with `reason: "invalid_span"`, prints dropped spans and unknown collections.

5. **Test Suite Expansion (`tests/test_hadith_spans.py`)**:
   - Expanded to 20 unit tests covering:
     - F1: Sliding-window concurrency submitting next task before slow call completes (`test_sliding_window_concurrency_f1`).
     - F2: Kind normalization and dropped items preservation (`test_kind_normalization_f2`).
     - F3: Anchors crossing footnotes matching without fallback (`test_locate_crosses_footnote_f3`).
     - F4: Word boundary expansion past `وَ` and hamza `ء` (`test_word_boundary_expansion_f4`).
     - F5: Neo4j safety with monkeypatched order (read -> delete -> write) and test-only type deletion on live DB (`test_neo4j_safety_unit_f5`, `test_neo4j_write_hadith_spans_stores_kind`).
     - F6: Raw file newline repair on resume (`test_raw_file_newline_fix_f6`).
