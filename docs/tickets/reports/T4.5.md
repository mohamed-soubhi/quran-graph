# T4.5 Report — 4b Hadith spans: regex cues + GLM anchors, gate on the gold set (agy + GLM)

## Deviations

1. **Shorter-anchor locator fallback:**
   - *What the ticket said:* GLM returns start/end anchor phrases (3–8 words), and `locate(text, anchor, window_start)` matches them directly against the segment's normalized text outside footnotes.
   - *What we found & did instead:* If GLM returns an anchor with minor word truncation or boundary variation, exact 3–8 word matching could miss the span. In `src/extract/locate.py`, we implemented a deterministic shorter-anchor fallback: when the full anchor needle is not found outside footnotes, it tries successively shorter prefixes (for start anchor, down to 3 words: `words[:k]`) and suffixes (for end anchor, down to 3 words: `words[-k:]`), returning a `LocateResult` with `used_fallback=True`.
   - *How many spans used fallback per run:*
     - Run 1: **0 / 23** spans used fallback (all 23 matched exact anchor phrases).
     - Run 2: **0 / 25** spans used fallback (all 25 matched exact anchor phrases).
     - Run 3: **0 / 23** spans used fallback (all 23 matched exact anchor phrases).
     (Fallback usage was 0 in the gold gate runs because GLM copied clean verbatim anchors; the fallback is verified via unit tests in `tests/test_hadith_spans.py` and protects against LLM token cutoffs in the whole-book run).

2. **Cue paragraph and window counts across the whole book:**
   - *What the ticket estimated:* 11,527 cue paragraphs.
   - *What we found:* Scanning all 1,911 segments with the updated `CUE_REGEX` (covering isnad, takhrij, and Prophet attributions outside `[[…]]` footnotes) matched **12,683 paragraphs** (which expand to **12,770 windows** after splitting paragraphs > 3,000 characters). The throughput benchmark tested a 100-paragraph sample and reports projections for both 11,527 (ticket baseline) and the full 12,683 / 12,770 paragraphs.

3. **Gate 4b errors (false positives and misses across 3 runs):**
   - *Target:* Precision ≥ 90 %, Recall ≥ 80 %, Mean IoU ≥ 0.90 in each of 3 runs. All 3 runs passed the gate comfortably.
   - *Run 1 miss (1):* W08 `[1355, 1461)` («قَالَ ابْنُ عَبَّاسٍ: مَكَثَ أَلْفَ سَنَةٍ، ثُمَّ قَالَ: إِن...»). Reason: Athar by Ibn Abbas without a classical transmission chain; GLM omitted it in Run 1 due to non-deterministic temperature 0 output.
   - *Run 2 false positive (1):* W50 `[1306, 1485)` («قَالَ أَمِيرِ الْمُؤْمِنِينَ عُثْمَانَ بْنِ عَفَّانَ، رَضِيَ...»). Reason: Uthman's quote with isnad extracted by GLM as an athar; this is an isnad narration from Uthman, but the gold set categorized it as commentary/not hadith.
   - *Run 3 miss (1):* W11 `[638, 693)` («وَأَخْرَجَهُ مُسْلِمٌ أَيْضًا، مِنْ طَرِيقِ الْأَعْمَشِ...»). Reason: Chained takhrij line after a hadith; GLM did not emit a separate span for this chained takhrij in Run 3.

## What Changed

1. **Extraction Contract v1.1 (`docs/extraction_schema.json` & `src/extract/models.py`)**:
   - Added `kind` enum (`"marfu"`, `"athar"`) to each span item.
   - Bumped schema `$id` to `https://quran-graph.local/schemas/extraction/1.1`.
   - Updated `HadithSpanAnchor` model with `kind: Literal["marfu", "athar"]`.
   - Updated `tests/test_extraction_contract.py` (8 contract tests passing).

2. **Cue finder and span pipeline (`src/extract/hadith_spans.py`)**:
   - `find_cue_paragraphs(text)`: identifies paragraph offsets (`\n\n` boundaries) where text outside `[[…]]` matches `CUE_REGEX`. Logs which cue fired.
   - `split_long_paragraph(text, para_start, max_len=3000)`: splits paragraphs > 3,000 chars at sentence boundaries (`.` / `:`), never cutting inside `[[…]]` footnotes or `﴿…﴾` quotes, with 1-sentence overlap.
   - `locate_and_check_anchors(...)`: calls `locate()` on the segment text, rejecting spans that fall strictly inside `[[…]]` footnotes or `﴿…﴾` quotes, spans > 6,000 chars, or unlocatable anchors. Merges duplicates. Produces standardized records with `kind`, `cue`, `collection_hint`, `number_hint`, `method: glm`, `source: run:<run_id>`, `model`.
   - `compute_iou` and `match_spans_one_to_one`: computes IoU and performs 1:1 greedy matching (threshold ≥ 0.5) against gold spans.

3. **GLM Client (`src/extract/glm_client.py`)**:
   - Implemented `extract_hadith_anchors(window_text, model=None, host=None, timeout=120.0)` using Ollama `/api/chat` with structured outputs via `format: ollama_format(...)`, `stream: True`, `temperature: 0`.
   - Robust JSON decoding supporting streaming and raw extraction.
   - 1 retry on HTTP/JSON failure.

4. **Anchor locator with shorter fallback (`src/extract/locate.py`)**:
   - Full 3–8 word matching on v2-normalized text outside footnotes.
   - Prefix fallback (start anchor down to 3 words) and suffix fallback (end anchor down to 3 words) if exact phrase is not found.
   - Returns `LocateResult(start, end, used_fallback=bool)`.

5. **Evaluation Script (`scripts/eval_4b.py`)**:
   - CLI: `python scripts/eval_4b.py --runs N [--model TAG]`.
   - Evaluates gold set windows against predicted spans, calculates precision, recall, mean IoU, IoU ≥ 0.90 count, kind accuracy, fallbacks, false positives, and misses.
   - Outputs runs to `data/interim/spans/hadith-gold-run<k>.jsonl` and summary to `logs/eval-4b-<timestamp>.json`.

6. **Throughput Benchmark (`scripts/hadith_throughput.py`)**:
   - CLI: `python scripts/hadith_throughput.py --sample 100 [--seed 42]`.
   - Benchmarks concurrencies 1, 4, 8 on sample cue paragraphs drawn from the whole book.

7. **Unit tests (`tests/test_hadith_spans.py`)**:
   - 6 tests: cue finder on W01 skipping footnotes; long-paragraph splitter preserving quotes/footnotes; anchor rejection inside quote/footnote; exact anchor locating on W01 [141, 657) and [658, 790); IoU matcher; shorter-anchor fallback.

### Cue Regex Pattern (`src/extract/hadith_spans.py`)
```python
CUE_REGEX: re.Pattern[str] = re.compile(
    r"(?:"
    r"[وف]?(?:حدثنا|حدثني|حدثت|حدث|اخبرنا|اخبرني|اخبر|انبانا|انباني|سمعت)"
    r"|"
    r"[وف]?(?:رواه|روى|روي|روينا|اخرجه|اخرجاه|اخرجوه|خرجه|علقه البخاري)"
    r"|"
    r"(?:قال رسول الله|عن رسول الله|عن النبي|[وف]?في الصحيح|[وف]?في الحديث|صح الحديث|[وف]?ثبت في صحيح)"
    r")"
)
```

### Extraction System Prompt (`src/extract/glm_client.py`)
```
You are an expert Arabic hadith extraction assistant.
Extract all HADITH spans (narrations, quotations, and chained takhrij lines) from the input Arabic tafsir window.
Return ONLY a JSON object strictly conforming to the schema.

Extraction rules:
1. WHAT IS A HADITH: A narration with an isnad (حدثنا / أخبرنا / سمعت), an explicit takhrij (رواه / أخرجه / أخرجاه + collector), or the Prophet's ﷺ direct words or acts («قال رسول الله ﷺ», «وفي الحديث»).
2. START ANCHOR: The first 3-8 words of the span, copied EXACTLY from the input text, starting at the introducing formula (e.g. «قال الإمام أحمد: حدثنا», «وقد رواه مسلم»). Leading connectives like «ولهذا» stay outside.
3. END ANCHOR: The last 3-8 words of the span, copied EXACTLY from the input text, ending after the last word of the matn or takhrij (including closing quotes). Sentence-final full stops stay outside.
4. TAKHRIJ: A takhrij line with its own isnad/chain (e.g. «وقد رواه مسلم عن أبي بكر ... عن الجريري به») is its own separate HADITH span. A chainless takhrij line (e.g. «وكذلك رواه ابن جرير», «وعلقه البخاري مجزوما») joins the hadith before it.
5. KIND: 'marfu' if the quoted route reaches the Prophet ﷺ; 'athar' if it stops at a Companion or Successor (e.g. Ibn Abbas, Ibn Umar). Base this on the quoted route as written.
6. NOT HADITH: Tafsir opinions with short routes or no transmission verbs (e.g. «قال علي بن أبي طلحة عن ابن عباس», «قال مجاهد: ...») are commentary, NOT hadith. Dream or story reports (even with isnad) are commentary, NOT hadith.
7. FOOTNOTES: Text inside [[...]] is an editor footnote. NEVER extract from [[...]], and anchors must never be inside [[...]].
8. COLLECTION HINT: Must be one of 'bukhari', 'muslim', 'abudawud', 'tirmidhi', 'nasai', 'ibnmajah', 'malik', 'ahmad', 'darimi', or 'other' (for any other source like Tabari, Tabarani, Bazzar, Ibn Abi Hatim), or null.
```
