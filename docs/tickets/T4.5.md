# T4.5 — 4b Hadith spans: regex cues + GLM anchors, gate on the gold set (agy + GLM)

**Goal:** a pipeline that finds hadith spans in Ibn Kathir: regex cues pick paragraphs, GLM returns start/end
**anchor phrases** (never offsets), the existing locator turns them into exact offsets. Pass gate 4b on the gold set
over 3 runs, and measure GLM throughput so Claude can plan the whole-book run.
**Out of scope:** the whole-book run and writing HADITH spans to Neo4j (next ticket, after the time estimate is approved);
linking to `Hadith` nodes (Phase 5); COMMENTARY and `INSIDE` (T4.6).

Read first: `docs/notes/phase4-annotation-rules.md` (what is and is not a hadith, where it starts and ends, kind),
`docs/extraction_schema.json`, `src/extract/locate.py`, `docs/decisions.md` (T0.5 results, 2026-11-03 hadith rules).

## Facts (measured by Claude)
- Gold set `data/gold/phase4.jsonl`: 50 windows (whole paragraphs; `segment_id`, `window_start`, `window_end`,
  `window_text`), **24 HADITH spans** in 20 windows (19 `marfu`, 5 `athar`), mean length 366 chars, max 826.
  Offsets are in the segment's original `text`. W44 has no hadith on purpose (dream report = COMMENTARY).
- Fixture W01 = `ibn-kathir:2:255-255:1`: hadith spans exactly `[141, 657)` and `[658, 790)`, both `marfu`.
- Cues on v2-normalized text over all 1,911 segments: 30,992 hits (حدثنا-type 17,406; رواه/أخرجه-type 7,106;
  قال رسول الله/عن النبي/وفي الصحيح-type 6,480). **11,527 paragraphs** (split on `\n\n`) contain a cue,
  7.12 M chars; paragraph length median 492, p90 1,146, max 14,259.
- T0.5: `glm-5.3-flash:cloud` took 37–97 s per 904-char paragraph (thinking model); output not deterministic at
  temperature 0 — a 6th run missed a whole span. Single runs are not evidence.
- Normalizer v2 already removes hamza seats and tatweel, so anchors match across hamza spelling (decisions T4.1).

## Steps
1. **Contract v1.1** — add `kind` to each span in `docs/extraction_schema.json` and `HadithSpanAnchor`
   (`"marfu"` = the route reaches the Prophet ﷺ; `"athar"` = stops at a Companion or Successor). This is reading the
   route, not grading. Bump `$id` to `…/1.1`; keep the old fields. Update `tests/test_extraction_contract.py`.
2. **Cue finder** `src/extract/hadith_spans.py`:
   - `find_cue_paragraphs(text) -> list[tuple[int,int]]`: paragraphs (original offsets, split on `\n\n`) whose
     v2-normalized text, **outside `[[…]]` footnotes**, matches the cue list. Put the cue regex in one constant;
     start from the three groups above and add what the gold set needs (log which cue fired).
   - Paragraphs longer than 3,000 chars: split at sentence ends (`.` / `:` followed by space or newline) into
     windows ≤ 3,000 chars, never inside `[[…]]` or `﴿…﴾`; overlap one sentence and de-duplicate located spans.
3. **GLM call** — new `extract_hadith_anchors(window_text, model=None) -> HadithSpanAnchorList` in
   `src/extract/glm_client.py` (keep the old offset function for the smoke test). `/api/chat`, `format` = the v1.1
   schema via `ollama_format`, `stream: True`, temperature 0, timeout, one retry on HTTP/JSON error, then log and skip.
   Prompt (English instructions, Arabic examples): the annotation rules table in short form; 2 few-shot examples
   **not taken from the gold set** — one with an isnad hadith followed by a chained takhrij (two spans), one with a
   «قال مجاهد» opinion (no span). Ask for anchors of 3–8 words copied from the input.
   Try `"think": false` in the payload; if the API rejects it or quality drops on the gold set, keep thinking on and
   say so in the report.
4. **Locate and check** — for each anchor: `locate(text, anchor, window_start)` on the **segment text**; reject
   (log with run id, never guess) when: not found; start or end falls strictly inside a `[[…]]` footnote or a `﴿…﴾`
   quote (use `find_footnotes` and `find_quotes`); span longer than 6,000 chars; duplicates (same start/end) merged.
   Output records like the gold set: `span_id`, `segment_id`, `start`, `end`, `type: HADITH`, `kind`, `cue`,
   `collection_hint`, `number_hint`, `method: glm`, `source: run:<run_id>`, `model`.
5. **Evaluation** `scripts/eval_4b.py --runs N [--model TAG]`: for each gold window, run steps 2–4 on the cue paragraphs
   that intersect `[window_start, window_end)`; keep predicted spans that overlap the window.
   Match predicted ↔ gold HADITH spans one-to-one by best IoU (IoU = intersection / union); a pair counts when IoU ≥ 0.5.
   Per run print: predicted, gold (24), matched, **precision, recall, mean IoU of matched pairs**, how many matched pairs
   have IoU ≥ 0.9, kind accuracy on matched pairs, false positives and misses by window id with their first 60 chars,
   GLM calls, total and mean seconds per call. Save each run to `data/interim/spans/hadith-gold-run<k>.jsonl` and a
   summary to `logs/eval-4b-<timestamp>.json`. Exit code 0 only if **every** run meets the gate.
6. **Gate 4b** (plan, Aya & Mohamed 2026-11-03): in each of ≥ 3 runs, precision **≥ 90 %**, recall **≥ 80 %**,
   mean IoU **≥ 0.9**; marfu and athar both count. Iterate on the prompt and cue list until it passes; **do not change
   the gold set or the thresholds** — if a gold span looks wrong to you, list it under Deviations for Claude.
7. **Throughput** `scripts/hadith_throughput.py --sample 100`: 100 cue paragraphs drawn with a fixed seed from the
   whole book; measure seconds per call at concurrency 1, 4 and 8 (thread pool), error/timeout rate, located vs rejected
   anchors, spans per paragraph. Print the projected wall time for all 11,527 paragraphs (and windows from step 2) at
   each concurrency. If concurrency > 1 gives HTTP 429 or errors, report it and stop at the level that works.
8. Tests `tests/test_hadith_spans.py` (no network): cue finder on W01's text finds the paragraph and skips cues inside
   `[[…]]`; long-paragraph splitter never cuts inside `[[…]]`/`﴿…﴾`; anchor checks reject a span that ends inside a
   quote or footnote; anchors made from the first and last 5 words of W01's two gold spans locate to `[141, 657)` and
   `[658, 790)`; IoU matcher on hand-made cases (exact, shifted, one-to-one). Mark any GLM test `@pytest.mark.network`
   or skip it when Ollama is unreachable.
