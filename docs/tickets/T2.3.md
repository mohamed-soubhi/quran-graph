# T2.3 — Extraction contract: anchors → offsets (Claude + agy)

**Goal:** GLM output for hadith spans follows the fixed contract `docs/extraction_schema.json` (written by Claude),
and deterministic code turns the anchor phrases into exact character offsets in the ORIGINAL text.
Background: `docs/decisions.md` 2026-10-30 (GLM returns anchors, never offsets).

## Inputs
- `docs/extraction_schema.json` — the contract. Do not change it; if something in it looks wrong, write it under
  "Deviations" in the report.
- `tests/fixtures/tafsir_sample.txt` (904 chars) and `tests/fixtures/tafsir_sample.expected.json` (gold offsets).
- `src/extract/models.py` — keep the old `HadithSpan` / `HadithSpanList` (the smoke test uses them).

## Steps
1. `src/extract/normalize.py`:
   `normalize_with_map(text) -> (norm: str, index: list[int])` — for each ORIGINAL character: skip it if its Unicode
   category is `Mn` (diacritics); otherwise append it after mapping أ إ آ ٱ → ا, ى → ي, ة → ه, and append its original
   index to `index`. So `len(norm) == len(index)` and `norm[k]` comes from `text[index[k]]`.
2. `src/extract/models.py`: add pydantic `HadithSpanAnchor` (`start_anchor`, `end_anchor`, `cue`, `collection_hint`,
   `number_hint`) and `HadithSpanAnchorList` (`spans`), matching the JSON schema field by field
   (`collection_hint` is a `Literal[...]` of the schema enum, or None).
3. `src/extract/locate.py`: `locate(text, anchor: HadithSpanAnchor, window_start=0) -> tuple[int, int] | None`,
   following `x-locator-rules` in the schema:
   - normalize text and both anchors; `s` = first match of the start anchor at or after `window_start`;
     `e` = first match of the end anchor at or after `s`; either missing → return None and log a warning;
   - `start = index[s]`; `end = index[e + len(norm_end) - 1] + 1`, then extend `end` over following `Mn`
     characters, then over following characters in `" ” » ) ] ﴾`;
   - return None (with a warning) if the start falls inside a `[[ … ]]` footnote.
4. `src/extract/glm_client.py`: a helper `ollama_format(schema: dict) -> dict` that removes keys starting with `x-`
   and `$id` / `$schema` before the schema is sent as Ollama `format`. No GLM call in tests.
5. `tests/test_extraction_contract.py`:
   - the schema file is valid JSON Schema (use the `jsonschema` package; add it to `requirements.txt` with a pinned version);
   - the field set of the schema item == the field set of `HadithSpanAnchor`; required lists are equal;
   - an example object for the fixture validates against the schema:
     Ahmad: start `قال الإمام أحمد: حدثنا`, end `عند ساق العرش`, collection `ahmad`, number null;
     Muslim: start `وقد رواه مسلم`, end `عن الجريري-به`, collection `muslim`, number null;
   - `locate` returns **exactly** `(141, 657)` and `(658, 790)` for those two anchors on the fixture text;
   - `locate` returns None for an anchor that is not in the text, and for one that only occurs inside the `[[…]]` footnote
     (e.g. start `وصحيح مسلم برقم`);
   - `normalize_with_map`: `len(norm) == len(index)` and the index is strictly increasing on the fixture.
